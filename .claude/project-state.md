## Current Milestone

Шаг 12 "продакшн-деплой" — **закрыт**. Сайт реально работает на `wedding-press.ru`:

- **Инфраструктура**: Selectel VPS (Ubuntu 24.04, `135.106.197.113`), Docker + Docker Compose, `docker-compose.prod.yml` (отдельный от локального `docker-compose.yml`) — сервисы `db`+`app`+`caddy`, наружу торчит только Caddy (80/443), `db`/`app` только во внутренней сети. Код на сервере в `/opt/wedding-press`, синкается вручную через `tar`+`ssh` (не git — репозиторий приватный, деплой-ключ на сервере не заводили).
- **Caddy** (`Caddyfile`) — автоматический HTTPS: apex/`www` отдельным статик-блоком (важно: `www` НЕ в одном блоке с apex — Caddy отдаёт TLS-политику по этому имени wildcard-блоку, а не статике, и раз `www` в конфиге не значился отдельно, сертификат для него молча не выдавался; лечится отдельным site-block'ом на apex без `www`), `*.<домен>` — on-demand TLS с `ask http://app:3000/api/caddy-ask` (эндпоинт, `app/api/caddy-ask/route.ts`, переиспользует `slugSchema`, явно разрешает apex+`www` отдельно от обычных слагов — иначе Caddy не может получить сертификат даже для статически заданных имён, если они попадают под wildcard-паттерн). `request_body { max_size 20MB }` — общий лимит тела запроса (фото+музыка).
- **Dockerfile**: `prisma.config.ts` резолвит `DATABASE_URL` уже на этапе `prisma generate` (не только рантайм) — `.env` в `.dockerignore`, поэтому нужен `ARG DATABASE_URL` в стадии `builder`, иначе билд падает с `PrismaConfigEnvError`. Прод-миграции/сидинг/`admin:set-password` гоняются не через слим `runner`-образ (там нет `node_modules`/tsx — только трейснутый `standalone`), а через отдельный `docker build --target builder` образ.
- **Фото/музыка**: аплоад с устройства в Selectel Object Storage (S3-совместимое). `lib/storage/s3.ts` (`uploadFile`, роутит по content-type в `photos/`/`music/` внутри бакета), `/api/upload` (публичный, рейт-лимит, до 15 МБ), `useFileUploadMutation`, кнопка `UploadFileButton` в `components/editor/block-content-forms.tsx` — рядом с ручным полем URL, не вместо него. **Важный готча**: публичное чтение объекта у Selectel идёт НЕ через S3 API endpoint (`s3.ru-6.storage.selcloud.ru`, там всегда 403 для анонимов), а через отдельный публичный домен бакета вида `https://<uuid>.selstorage.ru` (`S3_PUBLIC_URL`) — и объект должен быть залит с `ACL: "public-read"` явно.
- **Бэкапы БД**: `scripts/backup-db.sh`/`restore-db.sh`, крон на VPS (`0 3 * * *`, не через приложение — контейнер `app` пересобирается при каждом деплое). **Критичный готча**: "Публичный"/"Приватный" на Selectel — свойство всего бакета, ACL на объект не имеет значения (объект с `--acl private` всё равно был публично читаем в публичном бакете) — поэтому бэкапы обязаны лежать в отдельном приватном бакете (`wedding-press-backups`, `S3_BACKUP_BUCKET`), никогда не в одном бакете с публичными фото. Также `aws-cli` на свежем VPS не доверяет цепочке сертификатов Selectel из коробки (свой бандл устарел) — нужен `AWS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt` явно в скриптах.
- **Telegram**: у этого VPS (Selectel, RU) заблокирован исходящий доступ к `api.telegram.org` (`connect ETIMEDOUT` на `149.154.x.x`). Исходящие вызовы (`sendTelegramMessage`, `lib/telegram/index.ts`) идут через Cloudflare Worker-прокси (`old-lab-cc76.kaizervonshizer1488.workers.dev`, форвардит `/bot<token>/...` на `api.telegram.org`) — переключается через `TELEGRAM_API_BASE_URL` (пусто = напрямую, для локальной разработки). **Оказалось, блокировка не однонаправленная**: входящие вебхуки от Telegram (`/api/telegram/webhook`, привязка чата через "Подключить" в кабинете клиента) тоже упирались в таймаут — `getWebhookInfo` показывал `last_error_message: "Connection timed out"`, а в логах Caddy не было вообще ни одного запроса с IP-диапазонов Telegram (`149.154.x.x`, `91.108.x.x`), то есть соединение обрывалось до Caddy, не на уровне приложения. ## Architecture Decisions

- **Динамическое чередование фона** (`TemplateDefinition.alternatingBlocks: BlockType[]` + `BlockProps.alternateDark?: boolean`, вычисляется в `page-renderer.tsx` по позиции блока среди реально включённых блоков этого набора типов) — заменило хардкод "этот тип блока всегда тёмный". Причина: выключение одного блока в админке иначе оставляло два блока одного цвета подряд. Затрагивает только шаблоны, где задан `alternatingBlocks` (сейчас — Tuscany, Old Money); остальные шаблоны это поле не используют.
- `BlockProps` пополнился `coverPhotoUrl?: string` — контентное фото обложки (`blocksConfig.cover.photoUrl`) прокидывается и в другие блоки шаблона (используется в Old Money Timer), не дублируется как отдельное поле контента.
- Ни одно архитектурное решение из CLAUDE.md в этом этапе не менялось — только визуальные/шаблонные добавления поверх существующей архитектуры.

## Design Decisions

- **Moody Paper**: рваный край — реальная фотографированная текстура (обрезки `paper.png`, предоставленного пользователем), а не CSS `clip-path` — это осознанный "анти-паттерн", которого проект теперь явно избегает для любых будущих декоративных текстур (см. CLAUDE.md §11). Шрифт — EB Garamond + Golos Text (Unbounded пробовали первым, отклонён как "слишком дженерик боевой санс"). Тёмный `primary` (`#1E2118`) — базовый фон страницы; бумажный `background` (`#F1F0EC`, сэмплирован с реального фото) виден только внутри карточек `TornCard`. Финальный `accent` — `#6B6650` (приглушённый оливково-серый, в тон бумаге); первая попытка `#A9764F` (тёплая терракота) была отклонена как выделяющаяся на фоне бумаги.
- Приём "оверсайз + `overflow-hidden` + negative-translate" (`w-[130%] max-w-none -translate-x-[11.5%]` внутри `overflow-hidden`) — общий способ прятать физические углы полноширинных декоративных фото-текстур на краях экрана; закреплён как паттерн для будущих full-bleed декоративных изображений.
- Договорённость по процессу: если задача требует найти новое фото/декоративную текстуру (рваная бумага и т.п.), всегда сначала предлагать несколько вариантов со ссылками и дожидаться согласования, не выбирать и не встраивать самостоятельно (см. CLAUDE.md §9–10; было применено при поиске текстуры Moody Paper и должно применяться дальше).
- Pink Sketch: финальная рамка фото — тонкая рамка (`border`) + блюрная тень (`shadow-[6px_6px_10px_var(--color-accent)]`), не жёсткая 0-blur тень и не декоративная wobbly SVG-рамка (обе пробовались и отклонены).
- Демо-сайты (шаг 11): один и тот же контент/фото на всех 5 шаблонах — сознательный выбор, чтобы сравнение стилей было "при прочих равных". Фото — Pexels, подобраны и согласованы с пользователем; часть первого набора отклонена и заменена по явному критерию "европейская внешность, не полные типажи, как на изначальном фото обложки". Имена демо-пары ("Александр и Мария") взяты из фолбэка публичного конфигуратора, а не придуманы отдельно. Превью-миниатюры на лендинге — реальные скриншоты каждого демо-сайта (не стоковое фото — оно одно и то же у всех 5 и не различало бы стили визуально).
- **InvitationGate** (`components/page-renderer.tsx`, рендерится вместе с `MusicToggle` под тем же `features.music`, но НЕ в `previewMode`) — полноэкранный тап-гейт перед обложкой. Причина существования функциональная, не декоративная: браузеры разрешают автовоспроизведение со звуком только в ответ на настоящий клик/тап/нажатие клавиши, никогда на скролл — гейт гарантирует этот жест до того, как гость вообще увидит сайт, вместо того чтобы полагаться на случайный клик где-то на странице. Перебрано 4 варианта механики, все оставлены как отдельные компоненты для сравнения (`invitation-gate.tsx` — диафрагма/aperture, `invitation-gate-seal.tsx` — восковая печать, `invitation-gate-curtain.tsx` — раздвижные шторки, `invitation-gate-envelope.tsx` — конверт, финально выбран и подключён). Конверт — единственная фотореалистичная версия: одно настоящее фото конверта+печати (Vecteezy) разрезано на два независимо анимируемых CSS-слоя классическим спрайт-приёмом (`background-size: 100% 200%` + `background-position: top/bottom`), а не два отдельных ассета — линия сгиба на исходном фото легла ровно на 50% высоты, поэтому шов между слоями практически не виден. **Известная незакрытая часть**: лицензия на это фото не куплена/не оформлена (см. Known Issues) — задеплоено намеренно, с явным "решим отдельно" от пользователя, а не по недосмотру.
  - **Перф-фикс**: по фидбеку "конверт долго может подгружаться [на первом визите] — есть какие обходы?" — узким местом оказался сам файл, а не прокси/кэш: `envelope-seal.png` весил 1.5MB при 1514×1121px, хотя гейт показывает его всего в `w-[280px]`. Пересжат в `envelope-seal.webp`, 640×474, ~16KB (~95x меньше) — качество на реальном размере показа не отличимо. Плюс `<link rel="preload" as="image" fetchPriority="high">` прямо в компоненте (Next.js App Router поднимает такие `<link>` в `<head>` сам, откуда угодно из дерева) — браузер начинает грузить картинку сразу при парсинге документа, не дожидаясь применения CSS `background-image` после гидрации.
- **Editorial Ч-Б, редизайн под "vintage film texture"** — прежняя концепция (чистая кремовая "журнальная" бумага + терракотовый акцент) отклонена пользователем как не читающаяся как плёнка. Первый проход сделал все текстуры CSS/SVG-генерируемыми (turbulence-зерно, radial-gradient виньетка и лайт-лик) — сознательно, чтобы не повторять историю с лицензией конверта у InvitationGate. Пользователь явно отклонил этот подход: "мне нужны настоящие текстуры, фото со стока. как и договаривались, список ссылку и подтверждаем" — потребовал реальные стоковые фото вместо CSS-имитации, по уже действующему в проекте процессу согласования (CLAUDE.md §9–10, предлагать ссылки и ждать подтверждения). Итоговый (согласованный, подтверждённый) набор реальных фото — все с Pixabay/Freepik-Magnific, см. `public/images/CREDITS.md` за полными ссылками и лицензиями:
  - Обложка (`cover.tsx`): реальную текстуру (зерно+лайт-лик, Pixabay) пробовали через `mix-blend-mode: screen` поверх фото невесты/жениха — пользователь отклонил как "слишком едкий" на полноэкранном хиро; обложка вернулась к простому чёрно-белому фото + исходный нижний градиент под текст, без текстурного оверлея. Датастамп-таймкод (`DD.MM.YYYY`, JetBrains Mono, оранжевый с text-shadow-"свечением") в углу — остался, это не "фон", отдельный декоративный элемент.
  - Общий фон страницы (`theme.tsx`) — заменён с CSS-зерна на настоящее фото (`grain-noise.webp`, Freepik/Magnific), наложенное через `background-blend-mode: screen` (не отдельным `<div>`, а прямо в фоновых слоях wrapper'а) поверх сплошного цвета, `background-attachment: fixed` + `cover` (не тайлится, чтобы не читалось явным паттерном). Цвет фона сменён с тёплого крема (`#E9E1D2`) на нейтрально-серый, более похожий на цвет самой плёнки (`#D7D4CC`) — по прямой правке пользователя: "главный фон надо сделать более по цвету схожим к плёнке, не кремовый".
  - `TrimDivider` — не CSS-имитация перфорации, а реальный кадр из бесплатного векторного "Роль плёнки" (Freepik/Magnific), растеризован и обрезан локально по ImageMagick (RMSE-автокорреляция для подбора бесшовного периода повтора — тот же приём, что раньше для кружевной ленты); дырочки/окошки кадра прозрачные, не белые, чтобы `--color-background` просвечивал сквозь них корректно на любом фоне.
  - Галерея (`gallery.tsx`) и фото в «Наша история» (`story.tsx`) — получили реальные зерно/царапины (два разных ассета от upklyak, чередуются по чётности индекса в галерее, чтобы соседние плитки не выглядели одним и тем же паттерном).
  - «Наша история» дополнительно получила декоративный фон — обожжённая золотисто-чёрная катушка плёнки (Freepik/Magnific PSD/JPG от xadartstudio, фон вырезан локально `-fuzz -transparent white`), тонким полупрозрачным слоем позади текста; метафора "история = киноплёнка воспоминаний" выбрана вместо RSVP (там уже занята метафора письма/скрепки) по явному запросу пользователя "предложи идею, куда её расположить".
  - Таймер (`timer.tsx`) остался как в первом проходе — счётчик кадров плёночной камеры (тёмные ячейки, оранжевые моноширинные цифры), это чистый CSS/типографика, а не текстура, под запрос "настоящих текстур" не попадает.
  - Монограмма — пунктирная рамка + моноширинный шрифт, тоже без изменений во втором проходе.
  - Два из четырёх Freepik/Magnific-ассетов (JPG upklyak) потребовали входа в аккаунт Magnific (сделал сам пользователь — "я вошёл в аккаунт, продолжай"): бесплатный JPG-экспорт у этого автора упирался в "дневной лимит использования" без логина; PNG-экспорт для всех ассетов вообще платный (credits/подписка) — не запрашивался и не нужен, JPG с чёрной подложкой работает идентично прозрачному PNG под `mix-blend-mode: screen` (screen(чёрный, x) = x).
  - Палитра демо (`prisma/seed-demos.ts` dresscodePalette) и свотчи на лендинге (`components/landing/examples.tsx`) обновлены под новые цвета (`#D7D4CC` вместо `#E9E1D2`) оба раза — при первом проходе и после смены фона.
  - `TrimDivider` донастроен по прямой правке после первого показа: дырочки/окошки кадра сделаны не цвета фона страницы, а оранжево-чёрными (`linear-gradient(90deg, #140a06, #B8541F, #140a06)` вторым слоем под тайлом плёнки) — имитирует характерный оранжево-коричневый оттенок базы настоящей цветной негативной плёнки; сама полоса увеличена (`h-8 md:h-10`, было `h-5 md:h-6`) по запросу "чуть пошире и позаметнее".
  - Визуальная QA в браузере (desktop, реальный клик по гейту-конверту, скролл по всем блокам) — проведена в конце сессии, когда расширение Chrome подключили; выглядит корректно (обложка, таймер-счётчик кадров, разделитель, «Наша история» с баннером-катушкой, галерея с чередующимся зерном). **Не проверено**: mobile/tablet-брейкпоинты — `resize_window` не уменьшил реальный viewport в этой сессии (осталась desktop-ширина несмотря на успешный ответ инструмента), технический затык инструмента, не пропуск специально.
  - **Не сделано**: скриншот-превью демо на лендинге (`public/images/demo-previews/editorial-bw.jpg`) не переснят — устарел, показывает версию до обоих проходов редизайна.
- **Scroll-reveal для блоков — всех 5 шаблонов сразу** (по запросу "плавная анимация появления блоков, текста при скролле для всех шаблонов") — реализовано в ОДНОМ общем месте: `components/primitives/section.tsx` (стал Client Component) + новый хук `lib/hooks/use-in-view.ts` (IntersectionObserver, одноразовое появление — не скрывается обратно при скролле вверх). Сработало сразу на всех шаблонах без правок по каждому из них, т.к. каждый блок каждого шаблона уже рендерит контент через этот `Section`. Обложки (`Cover`) не анимируются — не используют `Section`, и это осознанно (они и так видны при загрузке). `prefers-reduced-motion: reduce` уважается через Tailwind-вариант `motion-reduce:` прямо в className (не в JS) — попытка сделать это через ранний `setState` внутри эффекта словила `react-hooks/set-state-in-effect` от React Compiler ESLint-правила, что и привело к CSS-варианту вместо JS-ветвления.
- **Скролл-эффект плёнки (Editorial Ч-Б, `TrimDivider`)** — по запросу "эффект скролла ленты? с чередованием - первая слева направо, 2я - справа налево" + явное уточнение "блок может быть удалён — это должно быть динамически". Лента каждого дивайдера сдвигается по горизонтали (`background-position-x`, не `transform` — paint-only свойство, не требует "сброса" смещения при бесконечном repeat-x в отличие от transform-марквея с дублированными треками) через scroll-listener + rAF, напрямую через DOM-ref, не через React state — та же логика, что у `FooterSpotlight` (см. резюме-проект/паттерн этого репозитория) для курсора: высокочастотное событие, лишние ре-рендеры не нужны. Направление чередуется **динамически по позиции среди фактически включённых блоков**, не хардкодом по типу блока — переиспользован ровно тот же механизм, что уже был у `alternateDark`/`alternatingBlocks` (см. выше), но как отдельная параллельная пара `alternatingDividers`/`dividerDirection` в `lib/templates/types.ts` + отдельный `Map` в `page-renderer.tsx` — не переиспользован сам `alternateDark`, т.к. тот прибит к семантике "тёмный/светлый фон", а не generic "чередование по позиции"; заводить одну неймингово нейтральную замену вместо обоих означало бы трогать уже работающие Tuscany/Old Money без необходимости. Тоже уважает `prefers-reduced-motion` (пропускает scroll-listener целиком, оставляя ленту статичной).
  - **Диагностика в сессии**: на машине, где шла разработка, включена системная настройка "уменьшить анимацию" (`matchMedia('(prefers-reduced-motion: reduce)').matches === true`) — из-за неё пользователь сначала не увидел ни сдвиг ленты, ни fade-in блоков при собственной проверке сайта; после объяснения подтвердил, что дело в этом, не в баге. Стоит иметь в виду при будущей визуальной QA на этой же машине — оба эффекта корректно "выключены" по accessibility-правилу, а не сломаны.
  - Полный `/feature-review`-цикл (код-ревью + все 3 брейкпоинта в браузере) не пройден до конца ни для одной из фич этой сессии — только tsc/eslint/prettier (чисто) + частичная desktop-QA в браузере + server-side проверка чередования направлений через `data-direction` (временный debug-атрибут, добавлен и убран в этой же сессии). CLAUDE.md §11 требует явного отчёта и подтверждения пользователя перед коммитом крупного изменения — в этом случае пользователь одобрил коммит явно ("и всё, комитим и пушим на прод") после серии итераций и объяснения diff'а.

## Known Issues

- Дата свадьбы в демо-сайтах захардкожена (`WEDDING_DATE` в `prisma/seed-demos.ts`, `2027-06-12`) — таймер на демо в какой-то момент "закончится". Нужно будет когда-нибудь перезапустить `npm run seed:demos` с обновлённой датой (теперь и на проде тоже — сидили туда в этой сессии).
- Фото демо-сайтов хотлинкаются с `images.pexels.com` (внешняя зависимость) — если Pexels удалит/переименует конкретный файл, картинка на демо перестанет грузиться (не упадёт — `isRenderableUrl`/`next/image` деградируют мягко, просто пропадёт фото).
- Админ-панель (`/admin/dashboard`, `/admin/leads`, `/admin/projects/[id]`) не проверена на mobile/tablet — пропущено при production-QA, пользователь отложил, а не отменил.
- RSVP-дубликаты по имени — ожидаемое поведение после фикса этой сессии (см. Current Milestone / Next Steps #5), не баг, но требует ручной сверки парой в личном кабинете, пока нет персональных ссылок гостям.
- Публичные формы (лид-форма, RSVP) без капчи — есть рейт-лимит (`lib/auth/rate-limit.ts`), но не полноценная защита от ботов. См. Next Steps #1.
- `next.config.ts` намеренно разрешает `next/image` фетчить любой `https`-URL — осознанный риск для пользовательских фото, комментарий в коде это фиксирует.
- Превью-скриншот Editorial Ч-Б на лендинге (`public/images/demo-previews/editorial-bw.jpg`) устарел после редизайна под "vintage film texture" — показывает старую кремовую версию, не переснят.
- **Лицензия на картинку конверта не оформлена**: `public/images/gate/envelope-seal.webp` (файл пересжат/переименован из `.png` в перф-фиксе — см. Design Decisions, но это тот же самый исходник, лицензионный статус не изменился) (используется в `InvitationGateEnvelope`) скачан с бесплатного превью-тира Vecteezy без покупки/атрибуции — задеплоено осознанно, с явным "решим отдельно" от пользователя. Нужно либо оформить Free License с атрибуцией конкретно этого автора на сайте, либо купить, либо заменить на чисто лицензированный источник.
